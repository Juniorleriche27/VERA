# VERA — Verifiable Analytics Agent workspace

A responsive, premium analytics workspace built with **Next.js App Router**, React, TypeScript (strict), Tailwind CSS v4, ESLint and Lucide icons.

## Local development

From the repository root, start the existing FastAPI backend in another terminal:

```bash
PYTHONPATH=. uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

The backend's default runtime planner is **Groq**, which requires its existing backend-only configuration. No provider secrets are read by the frontend. The local API CORS default allows `http://localhost:3000` (use this hostname for the frontend or configure `VERA_CORS_ORIGINS` on the backend as appropriate).

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:3000`. The frontend uses `NEXT_PUBLIC_VERA_API_URL=http://127.0.0.1:8000` by default. To override, create your own local `.env.local` based on `.env.example`. **Never add provider credentials to a `NEXT_PUBLIC_` variable.**

## User flow

1. API health is checked once at startup; retry is available when unavailable.
2. Click **Use demo dataset** for the three-minute video: the browser fetches the official synthetic CSV from `/demo/`, wraps it as a `File`, and uses exactly the same real `POST /datasets` upload path as a manual CSV. **Download CSV** remains available. Alternatively, upload any CSV by drag-and-drop or file selection. The API returns the safe schema/profile. Data rows stay on the analytics backend, while the planning model receives safe metadata only.
3. Use the official business question suggestion or write your own question. Press **Ctrl/Cmd + Enter** or the primary action to submit.
4. `POST /analyses` is synchronous. The UI displays an honest in-flight state and retains the complete response once received, including steps, verification reports, decision brief, visualizations and evidence.
5. After completion, the full-width results workspace presents the question from the API, an executed-steps timeline (including replan outcomes), the exact deterministic Decision Brief, Recharts line/bar visualizations and an expandable Evidence & provenance inspector with original results, full hashes and verification checks. The causal counterfactual interval is rendered as a shaded range band using the backend-provided lower and upper bounds; the frontend does not recalculate any statistical estimate. An investigation without a final verified brief remains clearly marked as needing review.

## Official demo CSV

`public/demo/vera_sales_campaign_demo.csv` is a static copy of **the single official source of truth** at `../demo/vera_sales_campaign_demo.csv`. It is explicitly **synthetic demonstration data**, not real business data. Users can download the CSV from the workspace and upload it to the live backend.

Whenever the official dataset changes, refresh the public copy and verify identity:

```bash
cp ../demo/vera_sales_campaign_demo.csv public/demo/vera_sales_campaign_demo.csv
npm run test:integrity
```

## Validation

```bash
npm run lint
npm run build
npm run typecheck
npm run test:integrity
```

No fake metrics, results, progress events, reasoning traces or verification badges are generated by the frontend. The API results come from the existing backend. Production deployments must configure the actual reachable API URL and CORS origins.
